# 同声 SameVoice 通信协议 v1

同声把一个局域网内的多台设备变成“音源”，并把所有音源实时混音后，从用户选定的那一台设备播放。

- 音频：48 kHz / 立体声 / 16-bit 有符号 PCM
- 音频分片：每包 240 帧（5 ms，960 字节负载）
- 发现：UDP 47821
- 控制：TCP 47820（端口被占用时主机可顺延，实际端口写在发现应答中）
- 音频：UDP 47822（实际端口写在握手应答中）
- 字节序：全部为 little-endian

> 设计取舍：v1 直接传 PCM，不做压缩。每路约 1.54 Mbps，适合同一 Wi-Fi 路由器下的 2–6 台设备，换取最低编解码延迟和最简单的部署。后续版本可无缝替换为 Opus。

## 1. 发现

音源设备从临时 UDP 端口向 `255.255.255.255:47821` 以及本机各网卡的子网广播地址发送：

```json
{"type":"query","proto":1}
```

输出端收到后，向请求来源地址单播应答：

```json
{
  "type": "offer",
  "proto": 1,
  "roomId": "a1b2c3d4e5f6",
  "name": "客厅电脑",
  "platform": "windows",
  "tcpPort": 47820,
  "mode": "balanced",
  "sources": 2,
  "pinRequired": false
}
```

`mode` 为 `balanced`（同步优先）或 `low`（最低延迟优先）。应答中的来源 IP 即输出端 IP。手动输入 IP 时直接假设 TCP 端口为 47820。

## 2. 控制连接

音源向输出端建立 TCP 连接，之后双方以 UTF-8 JSON Lines（单行 JSON + `\n`）通信，单条消息上限 4096 字节。

### `hello`（音源 → 输出端）

```json
{"type":"hello","proto":1,"name":"我的手机","platform":"android","pin":""}
```

输出端分配 32-bit `session` 与 64-bit 随机 `token`：

```json
{"type":"welcome","proto":1,"session":287454020,"token":"9f2c...","audioPort":47822,"name":"客厅电脑","mode":"balanced","sampleRate":48000}
```

`token` 是 16 位十六进制字符串。音频 UDP 包必须携带同样的 `session` 与 `token`，未知来源包会被静默丢弃。

### `start` / `started`

音源完成时钟同步后发送：

```json
{"type":"start"}
```

输出端回复 `{"type":"started"}`，音源开始发送音频。音源也可以先发音频，但 UI 会在 `started` 后才显示为“正在共享”。

### 其他消息

| type | 方向 | 说明 |
| --- | --- | --- |
| `heartbeat` | 音源 → 输出端 | 每 3 秒一次，15 秒无消息视为离线 |
| `stop` | 音源 → 输出端 | 停止共享，TCP 可以保持 |
| `mode` | 输出端 → 音源 | 输出端切换模式：`{"type":"mode","mode":"low"}` |
| `bye` | 双向 | 主动断开 |
| `error` | 输出端 → 音源 | `{"type":"error","message":"..."}` |
| `renamed` | 音源 → 输出端 | 更新显示名称 |

## 3. 音频 UDP 包

固定 36 字节头 + 960 字节负载：

| 偏移 | 长度 | 字段 | 说明 |
| --- | --- | --- | --- |
| 0 | 4 | magic | ASCII `SVA1` |
| 4 | 1 | version | `1` |
| 5 | 1 | type | `1` 音频, `2` 时钟请求, `3` 时钟应答 |
| 6 | 1 | flags | bit0 = 静音包 |
| 7 | 1 | reserved | 0 |
| 8 | 4 | session | uint32 |
| 12 | 8 | token | uint64（协议中以十六进制字符串传输） |
| 20 | 4 | sequence | uint32，音频包递增 |
| 24 | 8 | captureUs | 音频采集时刻，已换算到输出端单调时钟；时钟包中为发送端本地时刻 |
| 32 | 2 | payloadLength | 音频为 960；时钟应答为 16 |
| 34 | 2 | reserved | 0 |

音频负载为 240 帧 × 2 声道 × 2 字节。

### 时钟同步

音源每 5 秒用同一个 UDP socket 发 `PING`（type=2，`captureUs` = 发送端本地时刻 t1，`sequence` 为请求编号）。输出端立即回 `PONG`（type=3）：

- 头部 `captureUs` = 主机发送时刻 t3
- 负载 16 字节：t1、t2（主机收到时刻）各 uint64

音源收到后记 t4，计算：

```text
rtt    = (t4 - t1) - (t3 - t2)
offset = ((t2 - t1) + (t3 - t4)) / 2   // 主机时钟 - 音源单调时钟
```

取最近 8 个样本中 RTT 最小者作为基准，并做慢速平滑（每秒最多修正 2 ms），避免时间戳跳变。音频包的 `captureUs = 音源采集本地时刻 + offset`。

### 同步播放原理

输出端在启动输出时记录单调时钟 `t0`，并维护已经渲染的帧号 `f`。对于缓冲区中一帧音频：

```text
播放时刻(主机) ≈ t0 + f / 48000
捕获时刻(主机) = captureUs
安排的输出帧   = round((captureUs + targetBuffer - t0) * 48000 / 1e6)
```

所有音源使用同一个 `targetBuffer`（同步优先 240 ms；最低延迟 120 ms），所以采集于同一时刻的音频会在同一个输出帧被混音，实现音源之间的时间对齐。每个音源独立排队，迟到超过缓冲窗口的包会丢弃；队列被清空时输出静音，不会拖慢其他音源。

### 漂移与丢包

- UDP 丢包由输出端按时间戳自然填空，不做重传。
- 音源与输出端的晶振漂移由周期性 NTP 时钟同步限制；每 5 秒更新一次 offset。
- 每个音源可单独在输出端调节音量；混音器使用软限幅避免多路叠加削波。
- 音频不加密，只应在可信局域网使用。每会话随机 token 能防止误串流，但不能防止局域网内窃听。

## 4. 可靠性约定

- 丢弃 magic/version/session/token 不匹配的包，不做错误回应。
- 音频包 `payloadLength` 必须为 960，或合法范围内的 960（固定格式），其余丢弃。
- 超过 15 秒未收到控制心跳，或 TCP 断开，输出端释放该会话。
- 输出端停止时向所有音源发送 `bye`，并关闭监听端口。
- 设备发现只使用 IPv4；不支持跨网段、VPN、AP 隔离网络。

## 5. 默认端口与防火墙

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 47820 | TCP | 控制 |
| 47821 | UDP | 发现 |
| 47822 | UDP | 音频 |

Windows 首次监听时若弹出防火墙提示，请允许“专用网络”。也可以管理员运行仓库里的 `tools/allow-firewall.ps1`。
